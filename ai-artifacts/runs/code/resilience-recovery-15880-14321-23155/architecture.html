Architecture report — resilience-recovery

Language: typescript · Last completed phase: validated

Project plan

Goal: 슬립/백그라운드 복귀 후 '헤더만 남고 콘텐츠 사망'하는 치명 버그를 사인확정→자동복구→압박완화 3층으로 구조 해소. 진단 미확정(A WebContent사망 vs B JS fatal)을 존중해 모든 seam을 설계하되 구현은 증거-게이팅.

In-scope

  • #1 RootErrorBoundary (main.tsx 최상위 경계 = 사인 분기기; PaneErrorBoundary 패턴 재사용)
  • #2 Instrumentation: heartbeat + WebContent-death 감지 + 메모리/컨텍스트 watermark
  • #3 LosslessRecovery: topology 영속/복원 + 살아있는 Rust PTY 재attach 오케스트레이션
  • #4 PressureMitigation: WebGL 컨텍스트 상한 + 스크롤백 상한 (비가시 탭 렌더 일시정지는 기존 IO 활용)
  • Rust 계약 문서화(전부 1급/필수): report_webview_heartbeat, native WebContent termination+reload delegate(launch counter), read_death_evidence, persist/load/clear_recovery_session, persist_topology/load_topology, reattach_pty + bounded PTY replay ring-buffer. (스켈레톤 미생성; 별도 Rust planner run이 L2-for-A 선행)

Out-of-scope

  • 메서드 바디 구현 (다운스트림 implementer 소관)
  • Rust PTY-reattach 스켈레톤 코드 생성 (계약 문서화만; 필요 시 별도 planner run)
  • 실제 OS jetsam 확진 (런타임 계측 수집은 #2 구현 후 운영 활동)
  • 멀티윈도우 / 비-macOS 플랫폼 분기

Constraints

  • URL-scheme THREE-way invariant / localfile 토큰 규칙 등 기존 불변식 불침범
  • 공유메모리 dir은 PID 기반(memory.rs:21); reload는 PID 불변이라 dir·PTY 보존 — 설계 전제
  • 정상종료(Destroyed)→clear_memory_dir 능동삭제 경로 유지(복구는 Destroyed 미발화 경로 가정)
  • 버전 하드코딩 금지; tsc --noEmit 통과; 전 메서드 9-field docstring

Success criteria

  • 4개 권고의 모든 cross-boundary seam이 인터페이스/계약으로 명시됨
  • 구현 단계 게이트가 설계에 박혀 있음: #1+#2 우선 → 증거 → #3/#4 (shouldRecover 게이트)
  • RootErrorBoundary가 사인 분기기로 동작(잡힘=B, 미잡힘=A)하는 계약 정의
  • 복구 경로 무손실: topology 복원 + 기존 PTY 재attach 계약 정의
  • architecture.html + architecture.mmd 산출, tsc 통과(달성: TSC_OK)
  • round-2 4-peer convergent defects all reflected (10 items in revision_log); tsc --noEmit clean after revision
  • round-3 reload-crossing blocking finding (3-peer convergence) resolved via durable IRecoverySession + 2-phase orchestration; tsc clean

Open questions

  • Q1 RESOLVED: A detection = Rust IWebContentWatchdog (didTerminateWebProcess + durable last-beat), first-class/REQUIRED (not optional)
  • Q2 (in-place reload 1차; recreate-webview fallback). 복구는 reload 경계로 분리(prepare/resume)+durable IRecoverySession
  • Q3 RESOLVED: persist_topology/load_topology + persist/load/clear_recovery_session to PID-stable dir; proactive debounced
  • Q4 RESOLVED: Rust bounded per-session ring; replay flush precedes live resume(ordering) via pty-data stream
  • Collaborator 정책 CLOSED: alive PTY=reattach 필수 / dead PTY=핸들·로그 보존한 exited 타일(미드롭·미재spawn)
  • OPEN(implementer at #3): ring 보존 cap(bytes), blankObserved 컴포지터 probe 구현 방식

Package layout

  • src/components/IResilienceBoundary.ts (#1 boundary contract)
  • src/stores/IResilienceStore.ts (FSM store contract)
  • src/lib/resilience/ (#2 heartbeat/watermark/deathDetector, #3 topology/reattach/orchestrator, #4 webglBudget/scrollback)
  • src-tauri/src/commands/ (Rust 계약: reattach_pty/persist_topology/load_topology — 문서화만)
